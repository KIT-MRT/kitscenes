# Changelog

The `kitscenes` Python API. It follows [Semantic Versioning](https://semver.org) for **code**, separately from the dataset ([dataset versions](docs/dataset_versions.md)). Before `1.0.0`, a minor release (`0.2` → `0.3`) may change the interface and a patch release (`0.2.0` → `0.2.1`) fixes bugs, so pin `kitscenes>=0.2.0,<0.3` (or the git tag `v0.2.0`). After `1.0.0`, breaking changes bump major, backward-compatible features bump minor, bug fixes bump patch.

## 0.2.0

An alpha release: the API for dataset release **v2.0.0** (one zip per sensor and scene; 2,079 scenes in the default split `v2.0.0_default_geosplit`). It is a new API, not an update of 0.1.0: code written for 0.1.0 needs porting, and the dataset 1.0.x releases (one tar per scene) are read only by the legacy 0.1.0 ([dataset versions](docs/dataset_versions.md#legacy-dataset-v1x)).

What 0.2.0 offers:

- **The object model**: `kitscenes.open()` → `Dataset` → `Scene` → `Frame`. A root holds the scenes in `data/<split>/<scene_id>/`, as the release's zips (read in place) or as extracted folders. Frame tokens are `"<scene id>_<index:04d>"`, sensor names are enums, `scene.track` holds the recorded poses and `scene.files` the files behind a scene. [Conventions](docs/conventions.md) says which names are public.
- **One error model**: every missing piece of data raises a `kitscenes.Unavailable` with an `Availability` state that says why (or returns None with `missing="none"`); a corrupt or truncated zip member raises `kitscenes.ChecksumError` (CRC-32 check with `kitscenes.open(..., verify=True)`).
- **The `kitscenes` command line**: `download` (parts of the dataset by split, scene, sensor (`--components`), city, lidar generation or any scene-table column; pinned revision, `--update`, `--verify`), `extract`, `info`, `splits`, `transcode`, `pack`, `aerial`, `video`, `view`. `--dry-run` shows what `download`, `transcode`, `pack` and `video` would do. [Download](docs/download.md).
- **Sensors**: `frame.lidar(name)` gives the measured points of a sweep, deskewed; `rows=True` gives the stored rows with the scan layout, range images and rays without a return, `labels=True` adds the ground labels, and `frame.fused_lidar()` is all lidars as one cloud. Radar; cameras with DCT-reduced decoding; GNSS/INS and IMU from one Parquet file per topic; ego motion at any time (`scene.ego(t_ns)`), refined with the gyro where a scene has a valid IMU calibration, and from the past only with `frame.ego(causal=True)`; image corrections; a road-level ego frame (`frame="road"`) next to the base frame. [Sensors](docs/sensors.md), [GNSS/INS](docs/gnss_ins.md).
- **HD maps and map labels**: `kitscenes[map]` installs the KITScenes build of lanelet2 (`1.2.3+kitscenes4`); `scene.map` queries; vector-map labels cut exactly to the region, without duplicate lines, with lane segments and their topology: a `MapLabelSpec` describes them, `MLConverter.for_scene(scene, spec)` and `spec.labels(frame)` make them; `MapLabelSpec.maptr()` is the map benchmark preset; label recipes `"default"` and `"paper-v2.0.0"` (the labels of the v2.0.0 paper runs, on lanelet2 `1.2.3+kitscenes3`). [Maps](docs/maps.md).
- **SD maps**: `kitscenes.sdmap` reads the OpenStreetMap snapshots of the release (one per city and recording week, and the paper's 2026-05-03 snapshots): road graph, map matching, routing, junctions, the driven route (`scene.sd_route`) and its lanes on the HD map. [SD maps](docs/sdmap.md).
- **Training**: `SampleDataset`, `SampleSpec` and `collate` for a torch `DataLoader`: cameras, lidars, radars, ego past and future at fixed slots, temporal clips, map labels and SD maps. A batch holds images as (B, 3, H, W), decoded in the workers or on the GPU (`kitscenes.decode`); NVIDIA DALI readers in `kitscenes.dali`. [Training](docs/training.md).
- **End-to-end driving (experimental)**: ego status and driving commands for planners (`kitscenes.e2e`, `kitscenes.navigation`, `SampleSpec(navigation=...)`), with one numbering of the commands (`Command`: LEFT 0, STRAIGHT 1, RIGHT 2, UNKNOWN 3). The benchmark's navigation input is not final; the test-e2e scenes will ship their commands. [End-to-end driving](docs/e2e.md).
- **Split definitions**: the default split `v2.0.0_default_geosplit` is the release folders and the benchmark's split; `kitscenes.splits.SplitDefinition` and `kitscenes.open(..., split_definition=...)` use another one without moving files, `kitscenes splits export|check` writes one and checks its data-integrity rules. [Splits](docs/splits.md#split-definitions).
- **Scene table and filters**: recording metadata per scene (week, time of day, light, weather, road types, speeds, ...); `kitscenes.find_scenes(**where)`, `Dataset.filter(**where)`, `kitscenes download --where`. [Scene table](docs/scene_table.md).
- **KITScenes Aerial**: DOP20 orthophoto crops and DINOv3 feature tiles under every frame: `crops = ds.use_aerial(roi=...)`, then `crops[frame]`; `ds.use_aerial_features(...)` gives the features north-up by default. The tiles come by area: the DOP20 tiles with every download (`--no-aerial`), the DINOv3 features with the full download (`--no-aerial-features`) and with a filtered one only with `--aerial-features`. For imagery the release does not ship (another flight date, another source), `examples/download_aerial_tiles.py` fetches tiles from a WMS service into a tile folder of your own. [Aerial imagery](docs/aerial.md), [DINOv3 features](docs/aerial_features.md).
- **Downscaled camera images**: `kitscenes download --images half|quarter|eighth` and `kitscenes transcode` keep the cameras at a fraction of the size; `kitscenes pack` writes the release archive format. [Downscaled images](docs/transcode.md).
- **Visualization and lidar maps**: top-down plots, reprojection into the cameras (`examples/render_reprojection.py`), MP4 videos of scenes on the GPU (`kitscenes video`), the 3D viewer (`kitscenes-viewer` 0.2.0), voxel maps over many frames (`kitscenes.mapping`). [Visualization](docs/visualization.md), [Lidar maps](docs/lidar_maps.md).
- **Docs**: the pages in `docs/`, the notebooks in `notebooks/` as a learning path and runnable scripts in `examples/`.
